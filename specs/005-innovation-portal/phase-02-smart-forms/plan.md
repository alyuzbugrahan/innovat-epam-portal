## Data Model Change

### Schema Addition (`prisma/schema.prisma`)

```prisma
model Idea {
  id               String       @id @default(cuid())
  title            String
  description      String
  category         String
  categoryMetadata String?      // nullable JSON string: { fieldName: value }
  blindReview      Boolean      @default(false)
  status           String       @default("SUBMITTED")
  submitterId      String
  submitter        User         @relation(fields: [submitterId], references: [id], onDelete: Cascade)
  attachments      IdeaAttachment[]
  evaluations      Evaluation[]
  currentComment   String?
  reviewedAt       DateTime?
  createdAt        DateTime     @default(now())
  updatedAt        DateTime     @updatedAt
}
```

**SQLite note**: `String?` maps to `TEXT NULL`. No migration data-loss risk; existing rows get `NULL`.

### `categoryMetadata` Shape

The column stores a compact JSON string. The form produces one entry per idea:

```json
{ "techStack": "React, Node.js" }
{ "affectedTeam": "Engineering" }
{ "clientIndustry": "Healthcare" }
```

`null` when the category is "Other" or the idea predates Phase 2.

### Type Addition (`lib/types/idea.ts`)

```typescript
export interface Idea {
  // ... existing fields ...
  categoryMetadata: string | null   // add this line
}
```

## Migration Strategy

1. Run `npx prisma migrate dev --name add_category_metadata` from the project root.
   - Prisma generates a SQL migration that adds `categoryMetadata TEXT` to the `Idea` table with `NULL` as the default.
   - Existing rows remain valid — all get `NULL` for `categoryMetadata`.
2. Run `npx prisma generate` to regenerate the Prisma client.
3. No data backfill script is needed; the description-embed hack is read-only going forward. Existing ideas with embedded metadata in their description will continue to display correctly via the `parseIdeaDescription` path **only if** detail pages are temporarily kept dual-read. The clean cutover approach (recommended) is:
   - Migrate the schema.
   - Update all write paths to use the new column.
   - Update all read paths to use `idea.categoryMetadata` directly.
   - Remove the `parseIdeaDescription` call from all pages.
   - The `parseIdeaDescription` function itself can remain in `idea-metadata.ts` until a follow-up cleanup commit (it does not harm anything).

## Detailed Change Specifications

### 1. `lib/validations/idea.ts`

Add `categoryMetadata` to both schemas as an optional nullable string. Server-side cross-field validation (category requires metadata) is enforced in the service layer, not in the Zod schema, to keep the schema reusable for partial updates.

```typescript
categoryMetadata: z.string().max(500).nullable().optional(),
```

Export updated `CreateIdeaInput` and `UpdateDraftIdeaInput` types via `z.infer`.

### 2. `lib/db/repositories/idea-repository.ts`

**`create()` signature** — add `categoryMetadata: string | null = null`:

```typescript
async create(
  title: string,
  description: string,
  category: string,
  submitterId: string,
  blindReview: boolean = false,
  status: string = 'SUBMITTED',
  categoryMetadata: string | null = null
): Promise<Idea> {
  return prisma.idea.create({
    data: { title, description, category, submitterId, blindReview, status, categoryMetadata },
  })
}
```

**`updateIdea()` data object** — add `categoryMetadata` to the accepted data shape:

```typescript
async updateIdea(
  ideaId: string,
  data: {
    title: string
    description: string
    category: string
    blindReview?: boolean
    status: string
    categoryMetadata?: string | null
  }
): Promise<Idea>
```

### 3. `lib/services/idea-service.ts`

**`createIdea()`** — add `categoryMetadata: string | null = null` parameter; pass through to repository.

**`updateDraftIdea()`** — add `categoryMetadata: string | null | undefined` parameter; pass through to repository update call.

### 4. `app/api/ideas/route.ts` (POST handler)

Destructure `categoryMetadata` from `validationResult.data`:

```typescript
const { title, description, category, blindReview, status, categoryMetadata } = validationResult.data
// ...
const result = await ideaService.createIdea(title, description, category, user.id, blindReview, status, categoryMetadata ?? null)
```

### 5. `app/api/ideas/[ideaId]/route.ts` (PATCH handler)

Same pattern: destructure `categoryMetadata` from validated body; pass to `ideaService.updateDraftIdea(...)`.

### 6. `components/forms/idea-form.tsx`

**Remove** the description-append block (lines ~152–160 in current file):
```typescript
// DELETE THIS BLOCK:
if (extraFieldValue?.trim()) {
  description += `\n\n---METADATA---\n${JSON.stringify({...})}`
}
```

**Add** `categoryMetadata` to both the create POST body and the update PATCH body:

```typescript
// Build metadata JSON before sending
const extraFieldConfig = CATEGORY_FIELDS[selectedCategory]
const categoryMetadata = extraFieldConfig
  ? JSON.stringify({ [extraFieldConfig.name]: (formData.get(extraFieldConfig.name) as string)?.trim() || '' })
  : null
```

Include `categoryMetadata` in both the `POST /api/ideas` body and the `PATCH /api/ideas/:id` body.

**IdeaFormInitialValues interface** — replace `metadata?: Record<string, string | undefined>` with `categoryMetadata?: string | null`.

**Pre-populate extra field** — in the `useState` initialiser for the extra field value, parse `initialValues.categoryMetadata` with `JSON.parse` and extract the value for the current category field name.

### 7. Detail Pages

**`app/ideas/[ideaId]/page.tsx`** and **`app/admin/ideas/[ideaId]/page.tsx`**:

Replace:
```typescript
const { description, metadata } = parseIdeaDescription(idea.description)
```

With:
```typescript
const description = idea.description
const metadata = idea.categoryMetadata ? JSON.parse(idea.categoryMetadata) : null
```

The existing JSX that renders the "Category Details" section is unchanged — it already iterates `metadata` entries.

**`app/ideas/[ideaId]/edit/page.tsx`**:

Replace:
```typescript
const { description, metadata } = parseIdeaDescription(idea.description)
// ...
metadata: metadata || undefined,
```

With:
```typescript
// ...
categoryMetadata: idea.categoryMetadata,
```
